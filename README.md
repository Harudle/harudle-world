# 하루들 월드

하루들(https://www.harudle.com) 프로모션용 3D 웹 공간입니다. 1단계는 팝업북 로비와 '오늘의 특종' 신문 가판대를 담고 있습니다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5174
npm run build    # 타입 검사 후 dist/ 생성
npm run preview  # 빌드 결과 확인
```

## 배포

서버 공개 절차는 [DEPLOY.md](DEPLOY.md)에 있습니다.

브랜치에서 작업해 PR을 올리고, 승인을 받아 `main`에 합치면 자동으로 무중단 배포됩니다. 합치는 순간 실제 사이트에 나가므로 PR에서 충분히 확인합니다. 각자 컴퓨터에서 서버로 직접 복사하지 않습니다.

커밋에 개인 이메일이 공개되지 않도록 GitHub의 `noreply` 주소를 씁니다. 비밀값과 `deploy/.env`는 커밋하지 않습니다.

## 인기 피드 API

모달을 열 때마다 `GET /api/v1/feeds?sort=LATEST&size=50`으로 최신 글을 받아, 전날(KST) 올라온 글 중 1위를 고릅니다.

- 순위: 현재 좋아요 수, 댓글 수, 먼저 올라온 글 순서입니다. 전날 하루 동안 받은 좋아요 수는 API에 없어 쓸 수 없습니다.
- 전날 글이 없으면 글이 있는 가장 최근 날짜의 1위를 그 날짜와 함께 보여 줍니다.
- 최대 5페이지까지만 내려받으므로, 하루 글이 많아지면 백엔드에 날짜 조건을 추가하는 것이 좋습니다.

- `npm run dev`: Vite 프록시가 `/api`를 하루들로 전달합니다.
- 배포: 서버(`server/harudleProxy.ts`)가 피드 조회만 하루들로 전달하고 1분간 저장합니다. 하루들 CORS 설정은 필요 없습니다.

전시관은 `GET /api/v1/feeds?sort=POPULAR&size=50`을 최대 6페이지 받습니다. 메인 전시실에는 인기순 23점을 걸고 1위는 입구 맞은편에 크게 겁니다. 받은 좋아요 합이 큰 작가 8명은 메인 양옆 벽의 문으로 들어가는 별도 전시실을 받고, 방마다 좋아요순으로 최대 40점을 겁니다.

액자 이미지는 WebGL 텍스처라서 `/s3-image` 경로로 우리 서버를 거쳐 받습니다.

## 작가 체험 부스

메인 전시실의 부스나 "작가 체험" 버튼을 누르면 하루들에 게시한 만화가 전시관에 걸리는 과정을 안내하고, 그 아래 버튼으로 `https://www.harudle.com/login`을 새 탭으로 엽니다. 전시관은 인기순 피드 최대 300점에서 작품을 고르므로, 메인 전시실과 작가 방에는 그중 인기 있는 작품과 작가가 걸립니다.

## 하루들 휴대폰

메인 전시실 카펫 오른쪽의 큰 휴대폰 화면에 `https://www.harudle.com`이 그대로 떠 있어서, 걸어가서 화면을 누르고 스크롤하며 하루들을 쓸 수 있습니다. 웹 페이지는 three의 `CSS3DRenderer`로 캔버스 뒤에 깔고 화면 자리만 캔버스를 투명하게 뚫어 보여 줍니다(`src/scene/WebScreen.tsx`). 그래서 캔버스는 마우스를 받지 않고 바깥 상자(`data-scene`)가 3D 화면의 입력을 받습니다. 화면이 작게 보이면 휴대폰 옆 "크게 열기" 받침대나 "하루들 열기" 버튼으로 휴대폰 크기 창을 엽니다.

하루들이 `X-Frame-Options: DENY`를 보내는 동안에는 화면이 비어 보입니다. 하루들 쪽에서 이 헤더 대신 `Content-Security-Policy: frame-ancestors 'self' https://world.harudle.com`을 보내야 합니다.

## 함께 그리는 이젤

메인 전시실 카펫 오른쪽 앞에 네컷 칸이 그려진 이젤이 있고, 바닥에 이젤 붓이 하나 놓여 있습니다. 붓은 방 전체에 하나뿐이라 한 사람만 주울 수 있고, 주운 사람은 다른 사람 화면에서도 붓을 든 모습으로 보입니다. 붓을 든 채 이젤을 누르면 네컷 그림판이 열려 색과 굵기를 골라 자유롭게 그립니다. 그리는 선은 같은 방 사람의 이젤에 바로 나타납니다.

- 붓을 든 사람이 종이에 맞으면 붓이 그 자리에 떨어지고 그림판이 닫힙니다. 그리던 선은 닫히면서 마저 보내므로 이젤에 그대로 남고, 다시 주우면 이어서 그릴 수 있습니다.
- 줍기, 그리기, 새 종이는 서버(`server/easel.ts`)가 거리와 들고 있는 사람을 확인합니다. 규칙 값은 `src/data/easel.ts`와 `src/scene/gallery/layout.ts`에 있습니다. 한 장에 그릴 수 있는 점 수에 상한이 있습니다.
- 든 사람이 다른 방으로 가거나 나가면 그 자리에 붓이 떨어집니다. 2분 동안 그리지 않아도 내려놓습니다.
- DB에 저장하지 않습니다. 서버가 다시 켜지거나 30분 동안 아무도 그리지 않으면 새 종이로 돌아가고 붓도 제자리로 갑니다.
- 누구나 자유롭게 그리는 공개 그림이라, 지금은 붓을 든 사람이 "새 종이"로 지우는 것 말고는 따로 걸러 내는 장치가 없습니다.

## 아바타

처음 전시관에 들어오면 꾸미기 화면이 뜨고, 결과는 브라우저 `localStorage`에 저장됩니다. 옵션은 `data/avatar.ts`, 모양은 `scene/Avatar.tsx`에 추가합니다.

꾸미기 화면의 "함께 다닐 친구"에서 두들 동행을 고를 수 있습니다. 전시관의 설정 스위치와 같은 값(`data/settings.ts`)을 씁니다.

## 퀴즈 아케이드

로비 왼쪽 "오락실" 문이나 "퀴즈 아케이드" 버튼으로 들어가는 입구 홀입니다(`#arcade`). 뒷벽의 문 두 개로 노래, 드라마 맞추기 방에 들어갑니다(`#arcade-song`, `#arcade-drama`). 방에는 사용자가 등록한 문제만 걸리고, 예제 문제는 없습니다. 입구 홀은 40×28, 방은 34×26이라 한 곳에 100명이 있을 수 있습니다. 3D 코드는 `scene/arcade/`, 화면은 `ui/ArcadeSpace.tsx`, `ui/UserQuizModal.tsx`, `ui/RegisterQuizModal.tsx`, 방 목록은 `data/arcadeQuizzes.ts`에 있습니다.


## 사용자 문제 등록

문제와 소설관 만화는 하루들 "이벤트" 카테고리에 게시해 달라고 안내합니다(서버에서 강제하지는 않습니다).

"문제 등록하기"에서 하루들 피드 글의 공유 링크(`https://www.harudle.com/feeds/글ID`)와 정답을 내면 방 뒷벽 가운데부터 걸리고, 차면 옆 벽으로 갑니다(최신 15개, 나머지는 스크린 리더용 목록). 서버는 `server/quizzes.ts`입니다.

- 링크는 `GET /api/v1/feeds/글ID`로 실제 글인지 확인하고, 이미지 주소가 15분이면 만료되어 10분마다 새로 받습니다. 하루들에서 지운 글은 벽에서 내려갑니다.
- 정답은 서버에만 저장하고 채점도 서버에서 합니다. 답 시도는 문제당 분당 10번, 등록은 10분에 5번으로 제한합니다.
- 맞히면 입력한 닉네임이 맞힌 사람 목록과 액자 명패에 뜹니다. 로그인이 없어 닉네임 중복과 사칭을 막지 못합니다.
- 등록할 때 정한 비밀번호(scrypt로 저장, 문제당 10분에 5번 시도)로 내립니다. 비밀번호 찾기는 없으며, 잊으면 DB에서 지워야 합니다. 비밀번호 도입 전 문제는 등록한 브라우저에서만 내릴 수 있습니다. 서로 다른 접속자의 신고 3건이면 가려집니다. 복구는 DB에서 합니다: `sqlite3 .data/quizzes.db "UPDATE user_quizzes SET hidden = 0 WHERE id = 번호"`
- 배포 서버 환경변수: `QUIZZES_DB_PATH`(기본 `.data/quizzes.db`, 영구 디스크), `HARUDLE_BASE_URL`(테스트용)

## 릴레이 만화 소설관

로비 뒤쪽 "소설관" 문이나 버튼으로 들어가는 복도입니다(`#relay`). 3D 코드는 `scene/relay/`, 화면은 `ui/RelaySpace.tsx`, `ui/RelayViewerModal.tsx`, `ui/RegisterEpisodeModal.tsx`, 서버는 `server/relay.ts`입니다.

"다음 화 올리기"에서 하루들 피드 글의 공유 링크와 비밀번호를 내면 올라온 순서대로 이어 붙습니다. 이젤에는 최신 화, 벽 필름에는 최근 4화가 걸리고 뷰어로 최대 100화까지 정주행합니다. 내리기와 신고는 사용자 문제와 같습니다. 배포 서버 환경변수는 `RELAY_DB_PATH`(기본 `.data/relay.db`, 영구 디스크)입니다.

## 앉기

벤치를 누르면 걸어가서 앉고, 걷거나 바닥을 누르면 일어납니다. PC에서는 벤치 근처에서 C 키로도 앉고 일어납니다. 앉은 모습은 다른 방문자에게도 보입니다. 자리 맡기는 없어서 같은 자리에 겹쳐 앉을 수 있습니다.

## 작가의 방 크기

방 크기는 걸리는 작품 수로 정해집니다(`roomLayout`, `scene/gallery/layout.ts`). 작품이 늘면 가로세로를 번갈아 넓혀 모든 작품이 벽에 걸리는 가장 작은 방을 만듭니다. GPU 메모리 때문에 한 방에 최대 40점까지 겁니다.

## 응원 방명록

작가의 방 게시판이나 "응원 방명록" 버튼으로 글을 보고 남깁니다. 게시판에는 포스트잇 6장이 붙고, 글이 더 많으면 최근 글 30개 중에서 10초마다 무작위로 바꿔 붙입니다. 저장은 실시간 서버의 SQLite(`server/cheers.ts`)에 하고, 로그인이 없어 다음처럼 동작합니다.

- 내 글은 브라우저에 저장된 삭제 토큰으로 지웁니다. 다른 브라우저에서는 지울 수 없습니다.
- 서로 다른 접속자의 신고가 3건 쌓이면 글이 가려집니다. 복구나 강제 삭제는 DB에서 직접 합니다: `sqlite3 .data/cheers.db "UPDATE cheers SET hidden = 0 WHERE id = 글번호"`
- 링크가 든 글은 거절하고, IP당 분당 5건으로 제한합니다. IP는 저장하지 않습니다.
- 배포 서버 환경변수: `CHEERS_DB_PATH`(기본 `.data/cheers.db`, 영구 디스크에 두어야 합니다), `TRUST_PROXY=1`(리버스 프록시 뒤에 있을 때만)

## 터치 조작

터치 화면에서는 왼쪽 아래 조이스틱으로 걷고, 화면을 밀어 둘러보고, 두 손가락으로 확대합니다. 바닥을 눌러 걷기도 그대로 됩니다.

같은 와이파이의 휴대폰으로 확인하려면 `npm run dev -- --host`로 띄우고 터미널에 나온 Network 주소로 접속합니다.

## 실시간 관람

같은 전시실이나 오락실에 있는 방문자끼리 서로의 아바타를 볼 수 있습니다. 가까운 사람만 전신으로 그리고(PC 24명, 휴대폰 10명) 나머지는 간단한 인형으로 그립니다. 40명이 넘는 방은 위치를 초당 5번으로 줄여 보냅니다. 주고받는 값은 위치, 아바타 선택값, 닉네임, 채팅입니다. 채팅은 같은 공간에 있는 사람에게 전달하고 `server/chatLog.ts`의 SQLite에 닉네임과 글을 30일 동안 저장합니다(IP는 저장하지 않음). 공간에 들어오면 최근 대화 30개를 보여 주고, 100자까지, 10초에 5번까지, 링크 없이 보낼 수 있습니다. 배포 서버 환경변수는 `CHATS_DB_PATH`(기본 `.data/chats.db`)입니다. 보낸 글은 채팅창과 머리 위 말풍선에 뜨고, `가리기`로 그 사람의 채팅과 종이를 내 화면에서 숨길 수 있습니다. Space로 점프, Shift로 달리기, 사람을 직접 눌러 구겨진 종이를 던질 수 있습니다. F 키와 우클릭은 마우스가 가리키는 곳으로, 휴대폰의 던지기 버튼은 다음에 누른 곳으로 던지며, 사람이 없는 바닥에도 던질 수 있습니다. PC는 바닥의 동그라미로 떨어질 자리를 미리 보여 줍니다. 자동으로 겨냥하지 않고, 종이는 5초에 6번까지, 30칸 거리까지 던질 수 있으며 떨어진 종이는 5초 동안 남습니다. 바닥으로 던진 종이는 떨어지는 순간 그 자리(1칸 안)에 있는 사람에게 맞습니다. 맞으면 뒤로 쓰러져 약 3초 동안 움직일 수 없고, 쓰러진 뒤 8초 동안은 맞아도 다시 쓰러지지 않습니다. 닉네임은 처음 들어올 때 꾸미기 화면에서 정하며(선택), 가까운 방문자의 머리 위에 이름표로 뜨고 응원글과 정답자 입력칸의 기본값이 됩니다. 로그인이 없어 중복과 사칭은 막지 못합니다.

- `npm run dev`와 `npm run preview`에는 서버가 함께 뜹니다.
- 배포 절차는 [DEPLOY.md](DEPLOY.md)를 봅니다. `npm run realtime`(Node 22.18 이상)으로 서버만 따로 띄울 수도 있습니다.
  - 서버 환경변수: `ALLOWED_ORIGINS`(사이트 도메인, 쉼표 구분. 비어 있으면 모두 거절), `PORT`, `MAX_PLAYERS`(기본 150)
  - 사이트 빌드 환경변수: `VITE_REALTIME_URL=wss://서버주소/ws`. 없으면 같은 도메인의 `/ws`로 접속합니다.
- 서버에 닿지 못하면 전시관은 혼자 보는 상태로 동작하며 뒤에서 재접속을 시도합니다.

서버는 메모리에서만 동작하는 단일 인스턴스입니다. 여러 대로 늘리려면 위치를 공유할 저장소가 추가로 필요합니다.

## 새 구역을 붙일 때

- 3D 오브젝트는 `scene/`에 만들고 `LobbyCanvas.tsx`에 배치합니다.
- 재질은 `<Toon />`을 쓰면 같은 만화 톤과 외곽선이 적용됩니다.
- 한글 간판은 `useCanvasTexture`로 그립니다.
